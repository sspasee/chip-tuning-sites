# Проект: демо-лендинги для сервисов чип-тюнинга (Кемерово / Томск)

Ты — координатор. Сам ничего не собираешь и не пишешь: ставишь задачи подагентам (навыки в `.agents/skills/`), принимаешь отчёты, обновляешь PLAN.md.

## Память проекта
PLAN.md — единственная память. Начинай работу с его чтения. После КАЖДОГО шага: отметь чекбокс, допиши строку в «Лог изменений», обнови «Последнее обновление». Если токены кончатся, следующая сессия продолжит с PLAN.md.

## Правила проекта
1. Никогда не выдумывать данные бизнеса: нет данных — поле пустое, блок на странице скрывается.
2. Отзывы только пересказом, без имён авторов.
3. На каждой странице плашка «Демо-концепт, не официальный сайт, удалим по первой просьбе» и запрет индексации.
4. Стек: статика, один скрипт сборки (`template/build.py`), без фреймворков.
5. Мобильная вёрстка в приоритете.
(Исходник правил — ANTIGRAVITY.md.)

## Делегирование
У каждого подагента свой диапазон. В задаче всегда указывай: навык, список slug, зону записи. Отчёт подагента — до 3 строк.

**Браузер один (Playwright MCP, один Firefox).** Агенты, которым нужен браузер (chip-researcher, chip-photographer, chip-validator для этапов A, C, D), запускаются ПО ОДНОМУ: параллельные агенты конкурируют за вкладки и ломают друг другу сессию. Параллельно можно запускать только агентов без браузера (chip-copywriter). Ключ «researcher-1..3» в таблице ниже — это диапазоны, а не одновременные процессы.

| Роль | Навык | Бизнесы | Модель |
|---|---|---|---|
| researcher-1 | chip-researcher | KEM-01 … KEM-08 | Gemini 3.8 Flash |
| researcher-2 | chip-researcher | KEM-09, KEM-10, KEM-12 … KEM-16 | Gemini 3.8 Flash |
| researcher-3 | chip-researcher | TOM-01 … TOM-06 | Gemini 3.8 Flash |
| photographer | chip-photographer | все, по приоритету PLAN.md | Gemini 3.8 Flash |
| copywriter-1/2/3 | chip-copywriter | диапазоны как у исследователей | Gemini 3.8 Flash |
| validator | chip-validator | все | Gemini 3.8 Flash |

Сейчас доступна только Gemini 3.8 Flash, поэтому все роли работают на ней. Модель в Antigravity выбирается при запуске агента, в файле навыка её не задать. Когда вернутся Claude-модели, исследователей и копирайтеров можно перевести на Sonnet.

## Работа на одной лёгкой модели
- Давай подагенту небольшую пачку (2–3 бизнеса), а не весь диапазон сразу; после каждой пачки результат должен быть сохранён в файл.
- Проверяльщик обязателен после каждой пачки, а не только в конце фазы: на Flash ошибки в цифрах вероятнее.
- Подагент не уверен в значении — оставляет поле пустым и пишет об этом в отчёте. Догадка хуже пустого поля.

## Порядок фаз
Фаза 1: исследователи → data/raw/{slug}.csv (один файл на бизнес, общий CSV не нужен), фотограф → photos/, проверяльщик (этап A, D). Фаза 2: копирайтеры → content/, проверяльщик (этап B). Фаза 3: `python template/build.py` → sites/, проверяльщик (этап C). Фаза 4: деплой и аутрич. Следующую фазу начинай, только если проверяльщик не вернул БЛОКЕР.
